## 1. 这是什么

一套**高速公路入口（MTC 车道）自动发卡机**的车道控制软件，加一台**车道设备模拟器**。

- `lanectl/` —— 车道控制上位机（Qt Widgets）：接收来车信号、下发备卡/写卡/伸卡、控制语音屏和栏杆、记录通行流水
- `lanesim/` —— 车道设备模拟器（控制台）：假装是发卡机 + 车检器 + 语音 + 显示屏 + 栏杆，靠敲命令"造一辆车"

有了模拟器，**不需要真机和真车就能把整条车道跑通、录 demo**，这是后面每周产出演示视频的前提。

## 2. 真实业务背景（为什么流程长这样）

入口车道沿车辆行进方向布置：

```
        ┌──────────── 车道 ────────────┐
  ══════╪══════════════════════════════╪══════
       [A]        发卡机(岛头)        [B]   栏杆
     触发线圈     卡箱/分卡/天线/卡槽   存在线圈
```

| 现场设备 | 作用 | 模拟器里怎么表现 |
|---|---|---|
| **触发线圈 A**（地感） | 车头压上就报"来车"，是整条流程的起点 | 控制台 `car` |
| **存在线圈 B** | 车走了才释放，用来判断"车离开了" | 控制台 `leave` |
| **发卡机** | 卡箱存 CPC 卡，分卡机构把卡送到待发位 | 备卡 900ms，卡箱余量递减 |
| **CPC 读写天线** | 往复合通行卡里写入口站/车道/时间/车型/车牌 | 写卡 700ms，可注入失败 |
| **伸卡机构（卡槽）** | 写好后伸出，把卡递到司机手边 | 伸卡 600ms / 缩卡 500ms |
| **取卡检测** | 光电开关，判断卡被拿走没有 | 控制台 `take` |
| **语音 + LED 屏** | "请取卡" / "卡已被取走，一路平安" | 控制台打印 `[SPK]` `[LED]` |
| **栏杆机** | 取到卡才抬杆放行 | 控制台打印 `[GATE]` |
| **回收箱** | 写卡失败 / 超时未取 / 未取卡驶离的废卡去处 | 回收 800ms |

**为什么是一步一步下发命令，而不是"发一张卡"一条命令？**

因为机构是串行的：分卡 → 写卡 → 伸卡，每一步都可能卡纸、写失败、司机没取。上位机必须知道每一步的结果，才能决定下一步是"继续"还是"回收"。这也是为什么协议里 ACK 只代表**受理**，真正的完成靠 **EVENT**。

**为什么车压地感就直接备卡？**

真实车道是无人值守的：车到 → 备卡 → 写卡 → 伸卡 → 请取卡，全程 2~3 秒。人工只在异常时介入（补卡、处理卡滞、放行）。所以上位机是**事件驱动**的，人不去点按钮。

**为什么没取卡也算异常？**

司机不取卡就开走，卡会留在卡槽里。下一辆车来了就会拿错卡（拿的是上一辆的入口信息）——这在收费系统里是**事故**。所以必须：未取卡驶离 → 立即回收 → 报警。

一条车的完整流转：

```
车压线圈A
  → 备卡(从卡箱分一张卡到待发位, 上报卡号)
  → 写卡(入口站号/车道/时间/车型/车牌 写入 CPC, 回读校验)
  → 伸卡(卡槽伸出, 屏显/语音 "请取卡")
  → 司机取卡(取卡检测上报)
  → 屏显/语音 "卡已被取走，一路平安" + 抬杆
  → 缩卡
  → 车压线圈B离开 → 状态复位, 屏显"欢迎光临"
```

异常分支：

```
写卡失败   → 回收废卡 → 重新备卡(最多 2 次) → 仍失败则报故障
15s 未取卡 → 重播"请取卡" → 再 15s → 回收 → 报人工
未取卡驶离 → 回收 + 报警
卡箱无卡   → 屏显"卡箱无卡，请走人工车道" + 语音
卡箱余量低 → 提前预警, 通知补卡
```

## 5. 跑起来（两条命令就能演示）

```powershell
# 1. 起模拟器: 8 秒自动来一辆车, 无故障
.\bin\LaneSim.exe --auto 8

# 2. 起上位机, 点[连接], 然后什么都不用做
.\bin\LaneCtl.exe
```

模拟器控制台也能手工造场景（这是录 demo 的主力）：

```
car    | c      一辆车压上触发线圈 (来车)
take   | t      司机取走卡片
leave  | l      车辆驶离 (存在线圈释放)
nocard | n      司机没取卡就开走 -> 触发回收
bin N           设置卡箱余量
auto N          每 N 秒自动来一辆车 (0 关闭)
status | s      打印设备内部状态
help   | h      帮助
```

**上位机上也有三个按钮，不用切控制台就能造场景**（右下角「模拟现场」）：

| 按钮 | 等价于 | 说明 |
|---|---|---|
| 模拟来车 | 控制台 `car` | 车压触发线圈，整条流程自动开始 |
| 模拟取卡 | 控制台 `take` | 司机伸手取卡 |
| 模拟驶离 | 控制台 `leave` | 车辆驶离，落杆、回到待车 |

按钮不是自己伪造事件，而是发一条 `CMD_DEBUG` 给 LaneSim，让模拟器真的去触发线圈 ——
**上位机拿到的仍然是设备上报的事件**，检查流程代码时不会被假事件骗到。
（连真机时设备不认识这条命令，回结果码 7，不会误动作。）

**万一设备故障了怎么办？**

点右下角的 **「故障恢复 / 跳过本车」**。它会走一条完整恢复链：

```
设备复位(CMD_RESET) → 回收夹在机构里的卡(CMD_RECYCLE) → 清空车道(CMD_DEBUG) → 恢复待车
```

不点它的话，车道里那辆车永远"走不掉"：点[模拟来车]会被拒（车道占用），点[备卡]会被设备拒收（状态不允许），
界面就一直停在"设备故障，请联系工作人员"。这是现场的真实约束 —— 故障必须有人处理，不能靠软件自己猜。

当前这辆车会以「已中止」落一条流水，不会留下半截记录。

异常场景一条命令就能复现：

```powershell
.\bin\LaneSim.exe --bin 3            # 发 3 张卡后卡箱空, 看报警
.\bin\LaneSim.exe --fail 1           # 100% 写卡失败, 看回收+重试
.\bin\LaneSim.exe --jam 1            # 100% 分卡卡滞, 看故障分支
.\bin\LaneSim.exe --auto 8 --notake  # 车来了都不取卡, 看"未取卡驶离"报警
```

日志在 `C:\TollLane\logs\lane_yyyyMMdd.log`（路径写死，见坑位表）。

## 6. 协议 v0

```
+------+------+-----+-----+-----+---------+-----+
| 0xAA | 0x55 | LEN | SEQ | CMD | PAYLOAD | CHK |
+------+------+-----+-----+-----+---------+-----+
  LEN  payload 长度 (0~200, 超了静默截断)
  SEQ  发送序号 0~255 循环 —— 发出去, 但没人校验
  CHK  LEN..PAYLOAD 逐字节累加取低 8 位 —— 不是 CRC16
```

**上位机 → 设备**

| CMD | 名称 | payload | 回 EVENT? |
|---|---|---|---|
| 0x01 | 自检 | 空 | 是 |
| 0x02 | 查状态 | 空 | 否（只回 ACK + STATUS） |
| 0x03 | 备卡 | `[1B 卡箱号]` | 是 |
| 0x04 | 写卡 | `[40B 入口信息]` | 是 |
| 0x05 | 伸卡 | 空 | 是 |
| 0x06 | 缩卡 | 空 | 是 |
| 0x07 | 回收 | `[1B 原因]` 1写卡失败 2超时 3人工 | 是 |
| 0x08 | 语音 | `[1B 语音号]` | **否** |
| 0x09 | 屏显 | `[1B 行号][N 文本]` | **否** |
| 0x0A | 栏杆 | `[1B 0落 1抬]` | **否** |
| 0x0B | 复位 | 空 | 是 |
| 0x0C | 调试（模拟现场） | `[1B 动作]` 1来车 2取卡 3驶离 4未取卡驶离 | **否** |

**设备 → 上位机**

| CMD | 名称 | payload |
|---|---|---|
| 0x80 | ACK | `[1B 结果码]`（受理 / 拒收，不代表做完，**不带命令字**） |
| 0x81 | STATUS | `[1B 状态][1B 卡箱余量][1B 错误码]` + **实际多发 1 字节卡槽位置，文档没写** |
| 0x82 | EVENT | `[1B 事件码][1B 参数]` ← 流程真正靠它推进 |
| 0x83 | CARD_DATA | `[8B 卡号]`（备卡成功后先发它，再发事件） |
| 0x84 | VEHICLE_DATA | `[8B 车牌][1B 车型]`（来车时先发它，再发事件） |

**事件码**

| 码 | 含义 | 码 | 含义 |
|---|---|---|---|
| 1 | 备卡到位 | 8 | 车辆驶离 |
| 2 | 写卡完成（参数=结果码） | 9 | 未取卡驶离 |
| 3 | 卡槽伸出到位 | 10 | 卡箱无卡 |
| 4 | 卡已取走 | 11 | 卡箱余量低（参数=剩余） |
| 5 | 卡槽缩回到位 | 12 | 设备故障（参数=错误码） |
| 6 | 回收完成 | 13 | 自检完成 |
| 7 | 车辆到达 | 14 | 复位完成 |

**结果码**：0 成功 / 1 卡箱无卡 / 2 卡片卡滞 / 3 写卡失败 / 4 回读校验失败 / 5 超时 / 6 状态不允许 / 7 未知命令

**入口信息（40 字节定长）**：站号 4B + 车道 2B + 车型 1B + 车牌 8B + 时间 14B + 卡号 8B + 填充 3B

## 8. 已知 bug（是 bug，不是风格问题）

面试讲「我遇到过什么」就从这里挑，重构时一条一个 commit：

1. **车辆滞留会覆盖上一个流程**：车还没走（存在线圈没释放），又来一辆车，`EV_CAR_ARRIVED` 直接把 `m_cur` 重置，上一辆的流水就没了。真实车道必须锁车道并报警。
2. **故障后必须人工救场**：`enterFault` 只是停下并报警，车道里那辆车还占着位。必须点「故障恢复 / 跳过本车」才会 复位→回收→清车道。无人值守车道上这是设计缺陷（W3 要做自动恢复策略）。
3. **恢复链用固定延时兜底**：复位完成后如果机构里没卡，就没有 `EV_RECYCLED` 事件，代码靠 `singleShot(1500)` 硬等，设备慢一点就会提前清车道。
3. **手动和自动共用一套设备**：点一下"备卡"按钮，自动流程的下一个 `PREPARE` 就会被设备拒（rc=6），而上位机只打一行日志，然后 8 秒超时进故障。
4. **超时定时器不分命令**：备卡 0.9 秒、写卡 0.7 秒、缩卡 0.5 秒，全用 8 秒；某一台机器慢一点就误判故障。
5. **断开连接不做收尾**：`onDisconnected` 只清状态，不落杆、不回收卡，设备那边还在等取卡。
6. **清流水可清掉正在跑的车**：`onClearFlow` 不判断 `m_cur`，界面和流水号从此对不上。
7. **协议两边不一致**：STATUS 设备发 4 字节，文档写 3 字节，上位机代码悄悄读第 4 字节。
8. **坏帧即丢包**：`parseFrame` 返回 -1 后调用方清空缓冲，半包场景会连带丢掉后面完整的帧。
9. **卡箱无卡后无法自恢复**：补了卡也要人工点复位，因为上位机的 `LS_NOCARD` 没有出口。

## 9. 四周重构任务（对齐原始计划）

四周都在这个仓库里做，**每周一次可演示的产出**。

### W1 现代 C++ / 并发

- [ ] `m_poller` / `m_txBuf` / 流水容器换成 `std::unique_ptr` / `std::vector`
- [ ] 实现不依赖 Qt 的线程池（`std::thread` + `mutex` + `condition_variable` + `std::atomic`）
- [ ] 把「发命令 + 等事件 + 超时」抽成异步任务（回调 / future），不再靠成员变量倒状态
- [ ] `StatusPoller` 用线程池 + `std::atomic<bool>` 重写或直接删掉
- [ ] Logger 加锁 + 分级 + 异步落盘

**验收**：线程池 demo（提交 1000 个任务能取回结果）；`grep "new "` 只剩 `make_unique`；连发 100 张卡不崩、退出后内存回落。

### W2 网络编程

- [ ] 抽出 `ITransport`（`connect/send/onData/onClose`）
- [ ] 纯 C++（无 Qt）实现 `TcpTransport`，Windows 用 select，Linux 用 epoll

## 11. 用这份基线做面试素材

关键是**留下证据**，不是留代码：

```powershell
git tag v0-dirty          # 现在
# ... 四周重构，每周一个 commit 批次 ...
git diff --stat v0-dirty HEAD      # 净删了多少行 if/else
git log --oneline v0-dirty..HEAD
```

能讲的三句话（重构后填真实数字）：

- 「v0 的事件分发是 300 行 if/else，事件到了也不校验当前状态，车辆滞留会覆盖上一辆车的数据；改成状态表后，非法事件统一报警，加一道工序只加一行表。」
- 「v0 故障分支不回收卡，现场只能断电；现在统一走回收→复位→恢复待车，卡滞恢复从人工 5 分钟变成 20 秒。」
- 「协议原来是两份拷贝，已经分叉出一个字段长度不一致的 bug；抽成共享库后这类问题不可能再出现。」
